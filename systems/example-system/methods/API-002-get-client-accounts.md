# API-002 Активные счета клиента

> Контракт — [`../api/openapi.yaml`](../api/openapi.yaml), операция `getClientAccounts`.

## 1. Назначение и бизнес-логика

Возвращает активные счета клиента и признак основного счёта, чтобы партнёр мог указать реквизиты для зачисления. Требование: FR-05 (пример).

## 2. Вызов

| | |
|---|---|
| Метод и путь | `GET /v1/clients/{clientId}/accounts` |
| Идемпотентность | GET — идемпотентен |
| Таймаут на стороне потребителя | 10 с |

## 3. Алгоритм обработки

| № | Действие | Вызов / источник | При ошибке |
|---|---|---|---|
| 1 | Валидация `clientId` (V-01 из API-001) | — | 422 |
| 2 | Найти клиента (как в API-001, шаг 2) | АБС | 404 `CLIENT_NOT_FOUND` |
| 3 | Получить активные счета | АБС: `getActiveAccounts` | 503 при недоступности |
| 4 | Отметить основной счёт: признак `main` в АБС; если признака нет — первый счёт в UZS по дате открытия | — | — |

## 4. Маппинг полей ответа

| Поле ответа | Источник | Преобразование |
|---|---|---|
| `accountNumber` | АБС `account.number` | как есть, 20 цифр |
| `currency` | АБС `account.currencyCode` | числовой ISO 4217 → буквенный (860 → UZS) |
| `isMain` | правило шага 4 | — |
| `balance` | АБС `account.balance` | тийины → сумы, 2 знака |

## 5–11

Правила валидации, ошибки, негативные сценарии, НФТ и безопасность — как в [API-001](API-001-get-client-info.md), кроме:
