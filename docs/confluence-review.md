# Правило 5: владелец и дата пересмотра для страниц Confluence

Для того, что робот проверить не может: ТЗ, бизнес-логика, описания процессов.
Только встроенные макросы — работает и в Confluence Cloud, и в Data Center без плагинов.

## 1. Шапка на каждой странице ТЗ

В начало страницы вставить макрос **Page Properties** (Свойства страницы) с таблицей из двух колонок:

| | |
|---|---|
| Владелец | @упоминание аналитика |
| Статус | макрос Status: ЧЕРНОВИК / НА РЕВЬЮ / СОГЛАСОВАН |
| Последний пересмотр | дата (набрать `//` → выбрать дату) |
| Пересмотреть до | дата: последний пересмотр + 3 месяца |
| Артефакты в git | ссылка на тег, например `example-system-api-v1.2.0` |

Странице поставить метку `tz`.

Чтобы не собирать шапку руками — сохранить её как **шаблон страницы** пространства
(Настройки пространства → Шаблоны).

## 2. Реестр с просроченными страницами

На родительской странице раздела вставить макрос **Page Properties Report** (Отчёт по свойствам страниц):

- Метка: `tz`
- Колонки: `Владелец, Статус, Пересмотреть до, Артефакты в git`
- Сортировка: `Пересмотреть до`

Вверху таблицы окажутся страницы, которые пора пересмотреть.

## 3. Ритуал пересмотра (раз в месяц, 15 минут)

1. Открыть реестр, взять строки, где «Пересмотреть до» уже прошла.
2. Владелец открывает страницу и решает:
   - всё актуально → обновить «Последний пересмотр» и «Пересмотреть до»;
   - устарело → исправить (или завести задачу) и обновить даты;
   - больше не нужно → перенести в архив.
3. Страницы, которые генерирует робот (метка `autogen`), не пересматриваются — их актуальность держит git.
