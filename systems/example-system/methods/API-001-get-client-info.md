# API-001 Сведения о клиенте

> Контракт — [`../api/openapi.yaml`](../api/openapi.yaml), операция `getClientInfo`. Схемы здесь не дублируются.

## 1. Назначение и бизнес-логика

Метод позволяет партнёру проверить, что заявитель — клиент банка, и получить тип клиента и пол руководителя. Требования: FR-03, FR-04 (пример).

## 2. Вызов

| | |
|---|---|
| Метод и путь | `GET /v1/clients/{clientId}` |
| Идемпотентность | GET — идемпотентен |
| Трассировка | `X-Correlation-Id` пробрасывается в АБС |
| Таймаут на стороне потребителя | 10 с |
| Лимит | 20 запросов/с на партнёра |

## 3. Алгоритм обработки

| № | Действие | Вызов / источник | При ошибке |
|---|---|---|---|
| 1 | Проверить `clientId`: только цифры, длина 9 (ЮЛ) или 14 (ИП) | — | 422 `VALIDATION_ERROR`, АБС не вызывается |
| 2 | Длина 9 → поиск юрлица; длина 14 → поиск ИП | АБС: `searchLegalClient` / `searchEntrepreneur` | Не найден → 404 `CLIENT_NOT_FOUND` |
| 3 | Сформировать ответ по маппингу раздела 4 | — | — |

Диаграмма: [`../diagrams/API-001.puml`](../diagrams/API-001.puml)

## 4. Маппинг полей ответа

| Поле ответа | Источник | Преобразование |
|---|---|---|
| `clientId` | вход | как есть |
| `clientType` | длина `clientId` | 9 → `LEGAL_ENTITY`, 14 → `INDIVIDUAL_ENTREPRENEUR` |
| `name` | АБС `client.name` | как есть |
| `directorGender` | АБС `director.gender` (ЮЛ) / `client.gender` (ИП) | `1` → `MALE`, `2` → `FEMALE`, иначе `UNKNOWN` |
| `registeredAt` | АБС `client.regDate` | ДД.ММ.ГГГГ → ISO 8601 |

## 5. Правила валидации

| Код | Параметр | Правило | Код ошибки |
|---|---|---|---|
| V-01 | `clientId` | Только цифры, длина 9 или 14 | `VALIDATION_ERROR` |

## 6. Ошибки

| HTTP | code | Когда возникает | Что делать потребителю |
|---|---|---|---|
| 401 | `UNAUTHORIZED` | Неверный ключ или IP не в allowlist | Не ретраить |
| 404 | `CLIENT_NOT_FOUND` | Клиента нет в АБС | Не ретраить |
| 422 | `VALIDATION_ERROR` | Нарушено V-01 | Исправить запрос |
| 503 | `DEPENDENCY_UNAVAILABLE` | АБС недоступна или таймаут | Ретрай через `Retry-After`, не более 3 раз |

## 7. Негативные сценарии

| # | Сценарий | Поведение метода |
|---|---|---|
| 1 | Таймаут АБС (> 5 с) | 503 `DEPENDENCY_UNAVAILABLE`, `Retry-After: 5` |
| 2 | АБС недоступна | 503, circuit breaker открывается после 5 ошибок за 30 с |
| 3 | Повторный запрос | Метод только читает данные — повтор безопасен |
| 4 | Неизвестный исход вызова | Неприменимо: метод ничего не изменяет; клиенту — 503 |
| 5 | Частичный сбой | Неприменимо: один вызов АБС |
| 6 | АБС вернула неизвестный код пола | `directorGender = UNKNOWN`, событие в лог с уровнем WARN |

| Аспект | Значение |
|---|---|
